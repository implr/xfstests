# Tests excluded on ZFS.
#
# IMPORTANT: this list is calibrated against the ZFS built from our
# own branch, which carries 34 commits that are NOT in upstream
# OpenZFS. Only one of them has been submitted upstream: the block
# cloning double free fix behind generic/733 (openzfs/zfs#18853).
# The other 33 exist only here. Several tests absent from this list
# pass only because of those commits, so running this file against
# stock OpenZFS will produce failures it does not account for. Treat
# it as valid for this branch until the rest are upstreamed.
#
# Every entry here was measured, not assumed. A full -g auto run was
# made on five pool topologies (single disk at ashift 9 and 12, a
# 3-disk stripe, a 2-way mirror, raidz1) with only the five
# block-layer cases excluded, so each test below has a verdict from
# all five. Each group records what was actually observed.
#
# Fifteen tests were dropped because that run showed they no longer
# need excluding on this branch:
#   013, 139, 224, 269, 310, 476, 591 and 650 pass on all five.
#     013, 310, 476 and 650 were gated for a rangelock livelock and
#     an ARC OOM panic, neither of which reproduces here.
#     269 passes only because of our local commit "Return a negative
#     error from the writepage callback"; without it the writeback
#     loop warns and the test fails. 139 exercises direct I/O over
#     cloned blocks, which several of our local clone and Direct I/O
#     fixes touch, so it is unlikely to pass on stock OpenZFS.
#   118, 119, 144, 517, 563, 616 and 617 self-skip on all five. The
#     capability checks behind those skips are upstream, so these
#     removals do not depend on our commits.

# than excluded here.

# ARC memory deadlock. Passes on the four 4-CPU topologies but
# panics raidz1 (6 CPUs, 6 GiB) with "Kernel panic - not syncing:
# System is deadlocked on memory", reproduced twice. The write
# backlog outruns ARC reclaim and the kernel deadlocks instead of
# throttling. Same family as openzfs/zfs#18050. Capping zfs_arc_max
# for the VM size avoids it, so this is as much a tuning question as
# a bug, but it panics the machine, so it stays excluded until one
# or the other is settled.
#
# Note the passes above also depend on our local writepage error
# commit; before it this test failed on every topology.
generic/083

# Runs past any sensible limit. cp --reflink=always on a large
# sparse file never completes; killed at 900s on all five
# (openzfs/zfs#16014).
generic/303
