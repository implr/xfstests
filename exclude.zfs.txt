# fsx -e 1 post-EOF-page pollution.  Previously dismissed here as an
# fs-specific zeroing quirk ("not a ZFS correctness issue") -- that was
# WRONG.  It is a real ZFS bug: an mmap store into the last partial page
# past EOF was left in the page cache and, once the file was extended to
# cover it (a write past EOF, a truncate-up, or a fallocate), surfaced on
# read and was written back to disk (confirmed with zdb).  Fixed by zeroing
# the old partial-page tail on extend (zfs_write + zfs_extend); un-gated.
